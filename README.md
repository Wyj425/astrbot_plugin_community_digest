# 社区精选分享

**让 AI 机器人按群友或好友的兴趣，定时分享 B站、小红书和小黑盒的精选内容，再跟上一句自然的短评。**

你可以给不同的群和私聊设置不同主题，例如游戏群看 Apex、朋友私聊看英雄联盟。相同主题的搜索结果可以复用，每个会话分别记录发过什么。

<img src="logo.png" width="120" alt="社区精选分享插件图标">

## 能做什么

- **按兴趣订阅**：每个群、每个私聊分别选择主题标签。
- **定时或随机分享**：设置固定时间，或在指定时间窗口内随机推送。
- **每次精选一条**：从可用平台中选一条合格内容，附卡片和一句短评。
- **先评分再推送**：按相关性、信息质量、趣味性和时效性筛选内容。
- **复用候选**：同主题的搜索、评分结果供多个订阅者使用，减少重复检索。
- **参考近期聊天**：可选开启兴趣分析，结合本会话近期聊天和可用的 LivingMemory 记忆调整推荐。

适用于 **AstrBot 4.29.3 及以上、Python 3.12，QQ / OneBot 接入**。当前已验证 AstrBot 4.29.3。

## 安装前准备

在 **AstrBot → 插件市场** 安装「社区精选分享」，并准备以下功能：

| 用途 | 需要安装或配置 |
| --- | --- |
| 生成分享卡片 | [QQ卡片签名](https://github.com/Wyj425/astrbot_plugin_qq_card)，填写个人 Token |
| 分享 B站内容 | [B站内容读取](https://github.com/Wyj425/astrbot_plugin_bili_reader)，完成扫码登录 |
| 分享小红书内容 | [小红书内容读取](https://github.com/Wyj425/astrbot_plugin_xhs_reader)，按其教程部署服务并扫码 |
| 分享小黑盒内容 | [小黑盒内容读取](https://github.com/Wyj425/astrbot_plugin_heybox_reader)，完成扫码登录 |
| 内容评分和人设短评 | 在 AstrBot 中配置可用的聊天模型 |

先从 B站开始即可；小红书、小黑盒按需要开启，某个平台不可用时会跳过该平台。LivingMemory 用于可选的近期兴趣参考，可在基础分享配置完成后再启用。

## 两种配置方式

### 方式一：交给 Agent 配置（推荐）

将下面的提示词发给能操作你 AstrBot 的 Agent，并告诉它想给哪些群或好友推送什么内容：

```text
我已经从 AstrBot 插件市场安装了「社区精选分享」（community_digest）。
请阅读：
https://github.com/Wyj425/astrbot_plugin_community_digest

先检查 QQ / OneBot 连接、聊天模型，以及需要的内容读取插件和
QQ卡片签名插件。按各自 README 安装缺少的插件或读取服务。
平台扫码、设备验证和签名 Token 填写由我在后台完成，需要时提醒我。

将正确的 QQ 平台实例 ID 填入 platform_id，将评分和短评使用的
聊天模型提供商 ID 填入 provider_id。
先保持 enabled 关闭，向我确认目标群、好友和各自订阅的主题。
群聊默认参与，请把我不希望接收推送的群在 group_rules 中关闭；
私聊只添加我指定的好友。

为订阅主题建立 tag_library，配置各会话的 tags。
起步使用每天最多2条、09:00至24:00随机时间、80分起推、
候选保留3天，先关闭近期兴趣分析。
配置完成后核对订阅范围和依赖，再开启 enabled。
最后给我查看候选库、推送计划和发送记录的方法。
```

### 方式二：自己手动配置

1. 在插件市场安装所需的卡片、内容读取插件，按上表中的 README 完成 Token 配置和平台登录。
2. 在 **AstrBot → 机器人** 复制已连接 QQ机器人的 **平台实例 ID**。
3. 在 **AstrBot → 模型提供商** 找到用于评分、短评的聊天模型，复制其提供商 ID。
4. 打开 **插件 → 社区精选分享 → 配置**，填入 `platform_id` 和 `provider_id`。
5. 在 **共享标签库 `tag_library`** 中添加主题，例如“英雄联盟”，检索词可填“英雄联盟”“LOL”，别名填“LOL”。
6. 设置默认订阅标签 `default_tags`，并在 `group_rules`、`private_rules` 中为各会话选择自己的标签和平台。
7. 设置推送次数、时间、最低分和缓存天数。
8. 核对接收范围后，开启 `enabled` 并保存。

**群聊默认参与推送，未单独设置的群沿用全局规则。** 不接收的群请在 `group_rules` 中添加对应群号并关闭 `enabled`。私聊仅向 `private_rules` 中明确添加且启用的 QQ好友推送。

本插件本身无需另建服务器；小红书需要的读取服务命令见 [小红书手动部署教程](https://github.com/Wyj425/astrbot_plugin_xhs_reader/blob/main/docs/INSTALL.md)。

## 如何设置不同会话的兴趣

例如建立两个共享标签：

| 标签名称 | 检索词 | 可用别名 |
| --- | --- | --- |
| Apex | Apex、Apex英雄 | APEX |
| 英雄联盟 | 英雄联盟、LOL | LOL |

在某个群的 `group_rules` 中填写群号，将 `tags` 设为“Apex”；在某位好友的 `private_rules` 中填写 QQ号，将 `tags` 设为“英雄联盟”。

如果另一位好友也订阅“英雄联盟”，可以复用同主题的候选，无需为每个会话重新搜索和评分；每个会话仍有自己的推送历史和去重记录。

## 推荐起步设置

| 设置 | 用途 | 起步值 |
| --- | --- | --- |
| `schedule_mode` | 时间模式 | 随机时间 |
| `random_start` / `random_end` | 随机时间窗口，北京时间 | 09:00 / 24:00 |
| `daily_count` | 每个会话每天最多推送几条 | 2 |
| `min_gap_minutes` | 同一会话的两次随机推送最小间隔 | 90 分钟 |
| `min_score` | 推送最低分 | 80 |
| `selection_mode` | 从合格内容中怎么选 | 最高分 |
| `cache_ttl_days` | 候选保留时间 | 3 天 |
| `published_max_age_days` | 内容发布年龄上限 | 7 天 |
| `comment_mode` | 分享后跟的一句话 | 人设短评 |
| `model_daily_call_limit` | 每天全插件模型调用上限 | 12 |
| `interest_enabled` | 从聊天中分析近期兴趣 | 先关闭 |

固定时间模式下，在 `fixed_times` 填写如“12:30”“20:30”，每天最多执行 `daily_count` 次。群聊、私聊可以单独覆盖部分设置。完整字段见 [配置说明](docs/CONFIGURATION.md)。

## 如何筛选内容

评分由 **相关性 40 分、信息质量 25 分、趣味性 20 分、时效性 15 分** 组成，总分 100 分。前三项由模型判断，时效性由程序按发布时间计算；相关性或信息质量过低时，总分最多为 79 分。达到当前会话的门槛后，才进入可推送范围。

例如这次找到 95 分和 90 分的内容，先推送 95 分；下次可以直接使用仍未过期、未向该会话发过的 90 分候选。缺少合格内容时才按检索冷却规则补充。

分数是模型的筛选判断，适合控制推荐倾向；不同题材的可读性和实际兴趣仍需要通过订阅标签调整。

## 查看计划与推送结果

打开 **插件 → 社区精选分享 → 插件视图 → 精选候选库**：

- 查看共享标签、订阅会话和候选内容。
- 查看候选分数、过期时间、当天计划和历史状态。
- 使用 **导出候选库** 保存可读文档。

没有达到门槛、候选已过期、当天已发过或模型调用额度已用完时，可能跳过本次推送。重启不会重新抽取当天计划，也不会补发已经错过的时段。

## 近期兴趣推荐（可选）

基础推送正常后，可开启 `interest_enabled`。插件分析同一群或私聊中的近期真实聊天，参考可用的 LivingMemory 记忆，提取短期兴趣。

默认参考最近 72 小时，近期兴趣保留 3 天；每个会话每天最多分析一次，同时受全插件每日分析次数和模型调用总上限限制。各会话分别分析自己的兴趣。

## 常见问题

**装好后一直没有推送？**

首次安装默认关闭 `enabled`。检查开关、两个 ID、读取插件登录、卡片 Token、订阅范围以及候选库中的计划与历史状态。没有合格候选时会跳过。

**为什么卡片底部显示“其他来源”？**

当前图文卡片通道可能这样显示。小红书可以通过 `source_in_title` 在签名前添加平台名前缀；B站使用可跳转视频页的图文卡片。

**会调用几次模型？**

新搜索的候选会批量评分，人设短评通常另调用一次；开启近期兴趣分析后还会产生分析请求。已有候选可以复用评分，引用热门评论模式可减少部分短评生成请求。所有请求受 `model_daily_call_limit` 限制，签名服务另按服务方规则计费。

## 数据与备份

数据保存在 AstrBot 所在机器：

- 数据库：`data/plugin_data/community_digest/digest.db`。
- 候选库、标签库等可读导出：`data/plugin_data/community_digest/`。
- 配置：`data/config/community_digest_config.json`。

备份插件配置和整个数据目录，可以保留订阅、候选、计划和推送记录。Docker 部署时请持久化 AstrBot 的 `data` 目录。
